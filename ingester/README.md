# ingester

Turns Meshtastic MQTT deliveries into pseudonymised snapshot Parquet and loads snapshots into `raw` (ADR 0005). Nothing in it is a service and nothing runs unless started.

Modules:

- `keys.py`: the node pseudonym (HMAC-SHA-256 of the node number as 4 bytes big-endian under `NODE_ID_HMAC_KEY`, 64 hex characters), the low id byte, and the delivery key (`"delivery"`, the topic's byte length as 4 bytes big-endian, the UTF-8 topic and the payload). Known-answer tests in `tests/test_keys.py` fix both encodings; changing one after a snapshot exists is a key rotation.
- `topics.py`: topic class, the landed topic (every `!xxxxxxxx` node id replaced by its pseudonym) and the modem preset, by the channel names firmware v2.7.11 gives default channels.
- `decoder.py`: one delivery in, one allowlisted row, internet copy or counted drop out, with the `ing_03` decode status. Default-key decryption only.
- `allowlist.py` and `sql/raw_tables.sql`: the columns that may land and the `raw` tables that hold them; a test keeps the two equal. The DDL names its schema as `{schema}`, which `load.raw_ddl` fills with `raw` for every real load; every loader function that sends SQL takes a keyword-only `schema`, `raw` by default, and only the tests pass another.
- `counts.py` and `sightings.py`: copy, dropped and per-hour per-broker counts, and the broker flags and merged deliveries of `ing_01` and `ing_03`.
- `snapshot.py`, `parquet.py`, `finalise.py`, `readme.py`: hour file names, zstd Parquet with the allowlist schema, data content hashes, the merge at exit, coverage, README and the capture manifest's run fields and checks. The `<id>.partial/` folder, the sha256 manifest, verification and `raw.snapshot` registration are shared with every snapshot in `pipeline/common/snapshot.py`.
- `reduce.py`: the batch reduction of the 2026-10-22 archive into snapshot `meshtastic-capture-2026-10-22`. Its command is wired to that archive's folders, snapshot id and MeshSTL window. It ran once, on 2026-11-14, and cannot run again because its input was deleted the same day (ADR 0003, Consequences). `reduce_capture` takes any folders of capture JSON lines, and the tests run it on the synthetic fixtures. No future capture goes through it, since ADR 0005 limits the reduction to that one archive and capture runs pseudonymise in memory; `capture.py` imports only its `LICENCE` constant.
- `capture.py`: the core of the on-demand capture command in `docs/adr/0003-spike/capture.py`.
- `load.py` and `assets.py`: the insert-only loader and the hand-started Dagster asset `raw/mqtt_snapshot` with its `ing_07`, `ing_03` and `ing_04` checks.
- `link_pairs.py`: the pairs positioned at both ends in a capture snapshot (the ADR 0003 spike's union, 8 on `meshtastic-capture-2026-10-22`), found by running the spike's `analyze.py` on the snapshot rows, as the reproduction gate does, with the contract's rule for what a position is (`pos_01`, `pos_03`); every node's usable boxes inside the MSA over the capture, from either broker, with the `pos_04` precise flag and the node's stationary box under the amended `lnk_02`; and the box half-width rule, an inscribed square.
- `box_overlap.py`: the amended `lnk_02` overlap test in whole numbers (ADR 0003, Overlap amendment, 2026-11-17; Casey, PR #52, 3) and the stationary box, the smallest of boxes that all overlap one another.
- `tile_selection.py`: the tile's sites and receiver from those pairs by tile membership, the busiest-pair ranking kept for later use, the DEM extent check by the engine's rule, the pairs dropped for a node that straddles the tile edge or fails that check, and the sites alone for a run with no real receiver (`select_sites`).
- `engine_inputs.py`: the command that writes the real site and receiver layers for an engine run on one USGS 1 m tile, or with `--sites-only` the site layer alone (below).
- `settings.py`: `NODE_ID_HMAC_KEY`, `SNAPSHOTS_DIR` and the MQTT credentials, read once. `SNAPSHOTS_DIR` is also in `pipeline/common/settings.py` with the same default; the ingester keeps its own field so the capture and reduction start without the warehouse variables.

`NODE_ID_HMAC_KEY` is 32 random bytes written as 64 hex characters. Casey generates it with `python -c "import secrets; print(secrets.token_hex(32))"` and a copy is kept off this machine by Casey. It is read once, never logged, and the reduction and the capture command refuse to start without it.

Run:

- Tests: `make check` (the loader tests need the local stack and skip without it). The database tests never touch `raw` or `raw_dev_wh`: each builds the raw tables from `sql/raw_tables.sql` in its own `test_load_<12 hex>` schema inside a transaction that is rolled back, then drops that schema, and fails if its connection locked any table in `raw` or `raw_dev_wh` (`tests/raw_schema.py`; Casey, issue #55, item 10). `tests/test_raw_isolation.py` scans every test module for SQL against those two schemas.
- Reduction: `uv run --frozen python -I -m ingester.reduce`. It ran once, on 2026-11-14, and cannot run again: its input archive was deleted that day.
- Load: `uv run --frozen python -m ingester.load <snapshot id>`.
- Capture and gate: `docs/adr/0003-spike/README.md`.
- Engine inputs for a tile, from a checkout (it runs the spike scripts under `docs/adr/0003-spike/`), in Git Bash:

  ```
  unset VIRTUAL_ENV
  UV_SYSTEM_CERTS=true uv run --frozen python -I -m ingester.engine_inputs \
    --snapshot meshtastic-capture-2026-10-22 --tile x72y429 \
    --dem-snapshot 3dep-1m-mo-saintlouis-2017-x72y429 --expect-pairs 8 \
    --out C:/Users/Casey/mesh-terrain-data/configs/x72y429
  ```

  It writes `tx_sites_real.parquet` (`site_id`, `geometry`, `box_half_width_m`, `role`: `both_ends_gateway` or `gateway_only_gateway`) and `rx_real.parquet` (`rx_id`, `geometry`, `box_half_width_m`) in EPSG:26915, at the centre of each node's smallest box. `box_half_width_m` comes from `link_pairs.box_half_width_m` for that box: the smaller, east-west half of the box, so the engine's square is inscribed in it (Casey, issue #44, 1 (b): "an inscribed square that trims the long side"). Both files carry `mesh_terrain:positions` = `real` in their Parquet metadata. Casey, issue #44, 4 (a): ingest-eng's layers "real", the grid and fixtures "synthetic". The lead's interface note on issue #44 (2026-11-16) adds that a layer is `synthetic` only when every row is made up, and any real row makes it `real`. The engine does not read the key yet.
  - Both layers (with `--sites-only`, the site layer and the local run report) are written into `engine-inputs.partial/` inside the output folder and moved to their names only when all are complete. A refusal (exit 2) writes nothing. Any other failure raises after removing what the run wrote: the layers, the staging folder, and the output folder and parents it created. An existing layer or staging folder is refused and left as it is.
  - Positions by the amended `lnk_02` (ADR 0003, Overlap amendment, 2026-11-17). The command reads only a node's usable positions (15 bits or more) inside the MSA polygon (CBSA 41180, `dbt/seeds/msa_boundary.csv`, read through the spike's `load_area` and `Area`), from either broker and either source (Position or MapReport), over the whole capture, which stands in for the 7-day window. Coarse positions and positions outside the MSA are not read, and a node with no other position has no usable position. Two boxes are one place when they overlap: their stored integer coordinates differ by less than the sum of the two half-widths, 2^(31 - `precision_bits`) units of 1e-7 degree each, in latitude and in longitude; boxes that only touch do not overlap. The code tests `2 * abs(a - b) < 2**(32 - bits_a) + 2**(32 - bits_b)` so a 32-bit box, half a unit wide, stays in whole numbers. A node is stationary when it has at least one such position and all of them overlap one another; it is placed at its smallest box (the most `precision_bits`), and that box gives the layer's `box_half_width_m`. Firmware boxes that overlap are nested grid cells, so the smallest box is unique; if two overlapping boxes tied for the most bits the command would refuse rather than pick. Example: a gateway that sends a 15-bit box on the public broker and a 20-bit box inside it on MeshSTL is stationary and placed at the 20-bit box, about 46 m north to south where the 15-bit box is about 1.46 km. The pairs still come from the spike's rules, which test stationarity per run and overlap in floating point; moving them into tested ingester code is a later unit (Casey, PR #52, 4).
  - In or out of the tile (the lead's reading, decided without Casey, 2026-11-17): a stationary node is in or out by its placed box's centre, so a wider box of it that crosses the tile edge does not make it straddle; a node that is not stationary is in, out or straddling by the centres of all its usable boxes in the MSA.
  - Sites by tile membership (Casey, issue #44, busiest pair, 2026-11-17). The sites are the in-tile gateway of every pair that touches the tile, as the 2026-11-08 counts define touching: the both-ends pair's gateway, then each gateway-only pair's gateway in the capture's pair order (sorted by relayer pseudonym, then gateway pseudonym), each gateway once, `both_ends_gateway` first. The receiver is the both-ends pair's relayer. The 2026-11-08 note (`docs/measurements-2026-11-08.md`) named its sites as the gateway ends of the two busiest pairs without recording how it ranked them; that ranking rule is lost, and the x72y429 run is chosen by tile membership. The ranking stays in `busiest_two`, by link-hours over both runs, ties broken by receipts in those link-hours (Casey, issue #44, engine_inputs Q2 (a), 2026-11-16), for wherever a ranking is needed later (Casey, issue #44 comment 6956865492, 2026-11-17: "'Busiest' keeps (a), link-hours with ties broken by receipts, wherever a ranking is needed later; (c) is not adopted because it counts an hour twice when both brokers heard it"). Nothing selected depends on it. The stdout still shows each pair's link-hours over both runs, public and MeshSTL, and its receipts, for the local record, and a `sites by tile membership:` line stating the rule.
  - Without `--sites-only` (below), it refuses when the pair count differs from `--expect-pairs`, the tile does not hold exactly one pair with both ends, two pairs with only the gateway end and three pairs touching it (so none with only the relayer end), a node of a pair has no usable position in the MSA, a selected node that does not straddle the tile edge is not stationary (its usable boxes do not all overlap), the both-ends pair or a gateway-only pair is dropped (next item), the DEM snapshot is refused by the engine's reader, the output folder is inside a git checkout, or a layer exists.
  - Straddling nodes and dropped pairs (Casey, issue #44, engine_inputs Q1 (a), 2026-11-17). A node straddles the tile when it is not stationary and its usable boxes in the MSA lie on both sides of the tile edge. It is treated like a node that fails the DEM edge check: only its own pair is dropped, after the check that the tile still matches the 2026-11-08 counts, with a straddling node counted as touching the tile. So the counts run first over every pair, with a straddling node counted as in the tile. Then a pair is dropped when either of its nodes straddles, or a node of it that the run places fails the DEM edge check; a node shared with another pair stays in that pair unless it fails there too. Dropping the both-ends pair or a gateway-only pair refuses (exit 2) after the drop lines are printed and before anything is written, so the lead can bring it to Casey before `engine.prepare`. A selected node that is not stationary and does not straddle, two boxes inside the tile that do not overlap for example, is refused as before. With the count check as it is (three pairs touching, all three selected), an unselected pair with a straddling node is a fourth touching pair and fails the count check before any drop, so a drop that reaches the drop step is always of a selected pair. The straddle drop lines print before the count checks run (Casey, PR #51, (a): "The drop lines print before the count checks, locally only."), so every refusal shows which pair and which end caused it. Each names the pair's kind (`both-ends pair`, `gateway-only pair`, `other pair`) when those checks would pass, and `pair (kind not determined)` when one of them would refuse. A DEM edge check line needs the node's placed box, so it prints after placement; no drop line prints twice.
  - Worked example on the synthetic fixture (`tests/engine_inputs_fixture.py`): A to G1 has both ends in the tile, and B to G2 and C to G3 only their gateway. The sites are G1 (`both_ends_gateway`), then G3 and G2 (`gateway_only_gateway`, C to G3 first because C's pseudonym sorts before B's), and the receiver is A. With `busy_outside_pair=True`, D to E, east of the tile, has 6 link-hours, more than any other pair; it touches nothing, so the sites are the same. The gateway-only pair B to G2 has its gateway G2 inside the tile; with `straddler="G2"`, G2 also sent a box 10 km east, outside the tile. The tile check counts G2 as in the tile, so the counts still match; then B to G2 is dropped and the command prints `dropped gateway-only pair <B> to <G2>: gateway straddles the tile edge` and refuses with exit 2. With `straddler="B"` instead, B, the relayer of that gateway-only pair, also sent a box inside the tile: counted as in the tile it gives two pairs with both ends in it, so the command prints `dropped pair (kind not determined) <B> to <G2>: relayer straddles the tile edge` and then refuses on the one-both-ends-pair check. Three options add boxes the overlap rule reads as one place, so the layers stay as they are: `nested_g1=True` (G1 also sends a 15-bit public box holding its 20-bit MeshSTL box; G1 is still placed at the 20-bit box), `nested_g3=True` (G3 also sends a 15-bit box whose centre lies east of the tile edge; G3 is stationary, placed at its 18-bit box inside the tile, and does not straddle) and `ignored_a=True` (A also sends a box outside the MSA and a 13-bit box; neither is read).
  - Its stdout gives pseudonyms, roles, link-hours, box half-widths, the precise flag and the DEM check per node (the engine's rule on the DEM snapshot's bounds), and one line per end that drops a pair (both pseudonyms, `relayer` or `gateway`, and `straddles the tile edge` or `fails the DEM edge check`), never a coordinate. Those lines narrow where a node is, so they are read locally. Only the last `counts for issue #44` line is posted (Casey: counts only on issue #44); it gives the pair counts, the pairs touching the tile, the nodes selected, the DEM check passes and fails, and the pairs dropped in all and for each reason (a pair dropped for both reasons counts under each), with no pseudonym. The drop fields and the `extent ... fail` field stay for a later fallback, but without `--sites-only` every drop and every node failing the DEM edge check refuses, so these fields read 0 whenever the line prints; with it they can be above 0. On a refusal (exit 2), the issue gets only the fact that the command refused; the refusal text and any drop lines go to Casey in the session, not on the issue.
  - Sites only, the x72y429 run with no real receiver (Casey, 2026-11-17, engine_inputs (c)): add `--sites-only` to the command above. It is accepted only with `--tile x72y429`, since corridor runs keep the strict checks; any other tile refuses (exit 2) before anything is read. It writes `tx_sites_real.parquet` alone, with the same columns, roles and `real` marker, through the same staging folder, and never `rx_real.parquet`; terrain-rf-eng's `python -m engine.prepare x72y429 --folder <folder> --no-real-receivers` then takes the 400-point synthetic grid as the only receivers. The 2026-11-08 counts check still runs and prints one line, `counts check against 2026-11-08: pass` or `differs (...)` naming every count that differs, and does not refuse. The drop lines print at the same points as without the flag, and no dropped pair stops the run; since the counts check cannot refuse first, every straddle drop line names its pair's kind (`both-ends pair`, `gateway-only pair` or `other pair`), never `pair (kind not determined)`. The candidates are the in-tile gateways of the site rule above, but their roles follow the counted states, in which a straddling node counts as in the tile: a straddling relayer can make a second pair count as a both-ends pair, and that pair's gateway is then written as a second `both_ends_gateway` (decided without Casey, PR #57). A gateway is written only when it is stationary under `lnk_02`, does not straddle the tile edge and passes the DEM edge check. Each one left out gets a local line `left out <pseudonym> <role>: <reason>`, the reason being `straddles the tile edge`, `is not stationary under lnk_02` or `fails the DEM edge check`. A run with no site left refuses (exit 2) and writes nothing: `no site left; all <n> in-tile gateways were left out`, or `no site: no pair touching the tile has its gateway in it` when there was no candidate. No relayer is placed, so no receiver is chosen, a relayer that is not stationary does not refuse the run, and no relayer is DEM-checked. The `counts for issue #44` line ends with `sites written <n>, left out <m>; no real receiver written; relayers not DEM-checked`, with no pseudonym. An existing `rx_real.parquet`, site layer or staging folder in the output folder is refused, so the sites never sit beside an earlier receiver layer. Local run report (Casey, issue #55, 7: "Also write the counts line and every left-out gateway line into the local run report, not only the terminal. Nothing public."): beside the layer, through the same staging folder and only when the layer is written, the run writes `engine_inputs_report.md`, a heading, a local-only note, the two snapshot ids, and in a text block the drop lines, the counts check line, the site rule, each per-gateway line, the sites-only rule, each `left out` line and the counts line, in the order they printed. It names pseudonyms and ties them to roles and the tile edge, so it is local only, like the layer: the output folder is refused inside any git checkout, the report is never committed, posted or published, and only its last line, the counts line, goes on issue #44. A refusal writes no report (the terminal still prints the lines), and an existing report in the output folder is refused, so a report always belongs to the layer beside it. A run without the flag writes no report. `engine.prepare` accepts a folder holding the report: it refuses only its own four outputs and, with `--no-real-receivers`, `rx_real.parquet` (`engine/prepare/command.py`, `_check_folder`). `make engine` mounts the folder read-only with the config, and the engine reads only the files the config names. Worked example on the synthetic fixture: with `straddler="A"` the both-ends pair A to G1 is dropped (`dropped both-ends pair <A> to <G1>: relayer straddles the tile edge`) and the run still writes G1, G3 and G2 with exit 0; with `straddler="G2"` it writes G1 and G3 and prints `left out <G2> gateway_only_gateway: straddles the tile edge`; with `moved_g3=True` (G3 also sends a box 2 km west inside the tile) it writes G1 and G2 and prints `left out <G3> gateway_only_gateway: is not stationary under lnk_02`, where the run without the flag refuses; with `straddler="B"` (B also sends a box inside the tile) B to G2 counts as a second both-ends pair, so the run prints `counts check against 2026-11-08: differs (2 pairs have both ends in x72y429, not one; 1 pairs have only the gateway end in x72y429, not two); --sites-only reports it and does not refuse` and `dropped both-ends pair <B> to <G2>: relayer straddles the tile edge`, and writes G1 and G2 as `both_ends_gateway` and G3 as `gateway_only_gateway`; with `--expect-pairs 8` it prints `counts check against 2026-11-08: differs (5 pairs, not the 8 expected); --sites-only reports it and does not refuse` and writes all three.
  - The layers hold real positions, precise MeshSTL ones among them, and are never published (`pos_04`). Casey, issue #44, 2026-11-16: "Coverage outputs built from real gateway positions inherit the rule that precise MeshSTL positions are never published".

Fixtures: `tests/fixtures/mqtt/deliveries.jsonl`, built by `tests/fixtures/mqtt/build.py` from invented ids (`f1c70000` to `f1c7ffff`), invented text and invented positions, re-encrypted with the default key. Rebuild with `uv run python tests/fixtures/mqtt/build.py`; a test fails if the committed file differs from a rebuild.

Deliberately not here: any grid of made-up receivers, run config or path check for the engine (terrain-rf-eng's); any schedule, sensor or restart policy; any raw payload bytes, text, long or short name or public key in any output; any code that writes into a finished snapshot folder or deletes a `.partial` folder; any `update` or `delete` against `raw`.
