# ingester

Turns Meshtastic MQTT deliveries into pseudonymised snapshot Parquet and loads snapshots into `raw` (ADR 0005). Nothing in it is a service and nothing runs unless started.

Modules:

- `keys.py`: the node pseudonym (HMAC-SHA-256 of the node number as 4 bytes big-endian under `NODE_ID_HMAC_KEY`, 64 hex characters), the low id byte, and the delivery key (`"delivery"`, the topic's byte length as 4 bytes big-endian, the UTF-8 topic and the payload). Known-answer tests in `tests/test_keys.py` fix both encodings; changing one after a snapshot exists is a key rotation.
- `topics.py`: topic class, the landed topic (every `!xxxxxxxx` node id replaced by its pseudonym) and the modem preset, by the channel names firmware v2.7.11 gives default channels.
- `decoder.py`: one delivery in, one allowlisted row, internet copy or counted drop out, with the `ing_03` decode status. Default-key decryption only.
- `allowlist.py` and `sql/raw_tables.sql`: the columns that may land and the `raw` tables that hold them; a test keeps the two equal. The DDL names its schema as `{schema}`, which `load.raw_ddl` fills with `raw` for every real load; every loader function that sends SQL takes a keyword-only `schema`, `raw` by default, and only the tests pass another.
- `counts.py` and `sightings.py`: copy, dropped and per-hour per-broker counts, and the broker flags and merged deliveries of `ing_01` and `ing_03`.
- `snapshot.py`, `parquet.py`, `finalise.py`, `readme.py`: hour file names, zstd Parquet with the allowlist schema, data content hashes, the merge at exit, coverage, README and the capture manifest's run fields and checks. The `<id>.partial/` folder, the sha256 manifest, verification and `raw.snapshot` registration are shared with every snapshot in `pipeline/common/snapshot.py`.
- `reduce.py`: the batch reduction of the 2026-10-22 archive into snapshot `meshtastic-capture-2026-10-22`. Its command is wired to that archive's folders, snapshot id and MeshSTL window. It ran once, on 2026-11-14, and cannot run again because its input was deleted the same day (ADR 0003, Consequences). `reduce_capture` takes any folders of capture JSON lines, and the tests run it on the synthetic fixtures. Its manifest's `brokers` lists only the brokers with at least one capture file read, even when none of a file's records falls inside the window (Casey, issue #55 comment 7017280290, item 1). Before writing anything it refuses a run that finds no capture file in any folder (`NothingToReduceError`) and a `SnapshotInfo` whose `brokers` does not hold exactly one host per broker (`ValueError`, `check_broker_hosts`). Only that count is checked: the hosts are read in `Broker` order, public first, then MeshSTL, and the order itself is not checked. No future capture goes through it, since ADR 0005 limits the reduction to that one archive and capture runs pseudonymise in memory; `capture.py` imports only its `LICENCE` constant.
- `capture.py`: the core of the on-demand capture command in `docs/adr/0003-spike/capture.py`.
- `load.py` and `assets.py`: the insert-only loader and the hand-started Dagster asset `raw/mqtt_snapshot` with its `ing_07`, `ing_03` and `ing_04` checks.
- `link_rules.py`: the contract's link-hour rules, `lnk_01` to `lnk_06`, over rows shaped like `raw.mqtt_message`, both brokers merged, in the contract's order (`lnk_04`): every row's outcome, every (relayer, gateway, hour) with a counted receipt, and the data-quality counts `lnk_01_direct_hop_contradicted` (Casey, PR #66, Q4 (a)) and the hours dropped for more than one box. A broadcast's gateway copies, matched by node, `packet_id` and stored values, are one position, timed by the first copy and precise if any copy qualifies (ADR 0003; `tests/test_link_rules_broadcasts.py`). It passes every case of the conformance fixture `tests/fixtures/link_rules/` (`tests/test_link_rules.py`).
- `link_cells.py`: cells and boxes under `lnk_02`, `lnk_05` and `pos_01`: the half-open cell from the firmware's low edge, the integer overlap test, the 40 m floor `STATIONARY_FLOOR_M`, the box around merged fixes, the WGS84 half-widths and the geodesic between box centres.
- `msa.py`: the MSA polygon from `dbt/seeds/msa_boundary.csv` as a point test on stored 1e-7 degree integers.
- `link_pairs.py`: the pairs of a capture snapshot under `link_rules`, each with the box its counted receipts used at each end over its kept hours (Casey, issue #44, 2026-11-17; issue #55 comment 6985802330, item 2, (b)); the pairs whose kept hours used more than one box at an end, with those boxes, for `tile_selection` to drop after the counts check; the kept pairs whose hours not kept show another box, to report; and every node's boxes, the ones its pairs with one box per end used.
- `tile_selection.py`: the tile's sites and receiver from those pairs by tile membership, each node at the one box its pairs used, the busiest-pair ranking kept for later use, the DEM extent check by the engine's rule, the pairs dropped for a node that straddles the tile edge or fails that check, and the sites alone for a run with no real receiver (`select_sites`).
- `engine_inputs.py`: the command that writes the real site and receiver layers for an engine run on one USGS 1 m tile, or with `--sites-only` the site layer alone (below).
- `settings.py`: `NODE_ID_HMAC_KEY`, `SNAPSHOTS_DIR` and the MQTT credentials, read once. `SNAPSHOTS_DIR` is also in `pipeline/common/settings.py` with the same default; the ingester keeps its own field so the capture and reduction start without the warehouse variables.

`NODE_ID_HMAC_KEY` is 32 random bytes written as 64 hex characters. Casey generates it with `python -c "import secrets; print(secrets.token_hex(32))"` and a copy is kept off this machine by Casey. It is read once, never logged, and the reduction and the capture command refuse to start without it.

Run:

- Tests: `make check` (the loader tests need the local stack and skip without it). The database tests never touch `raw`, `raw_dev_wh` or `raw_dev_ta`: each builds the raw tables from `sql/raw_tables.sql` in its own `test_load_<12 hex>` schema inside a transaction that is rolled back, then drops that schema, and fails if its connection locked any table in `raw`, `raw_dev_wh` or `raw_dev_ta` (`tests/raw_schema.py`; Casey, issue #55, item 10). The lock check does not see a read made inside a savepoint that was rolled back, since that releases its locks. `tests/test_raw_isolation.py` holds the scan; its `ALLOWED` list names, by file and function, the matches that are not SQL. Every test connects as the test role, which has no privilege on those three schemas, so a write that gets past both checks still fails (`tests/test_db_role.py`, PR #74).
  - What the scan matches in every test module, outside docstrings, ignoring case:
    - text in a string, bytes or f-string literal where a watched name, as a whole word and quoted or not, is followed by a dot, with or without spaces before it, including a dot at the end of the text (`"delete from raw." + table`);
    - text where `search_path` is followed, before the next semicolon or line end, by a watched name as a whole word (`set search_path to public, raw`, `options="-c search_path=raw"`);
    - a string or bytes literal, or an f-string's literal part, that is, or ends with, a watched name as a whole word not preceded by a dot (`"raw"`, `f"raw{SUFFIX}"`, `"select * from raw" + "." + table`), however it is then used;
    - any name, attribute or import called `RAW_SCHEMA` or `REAL_SCHEMAS`.
  - What it does not see, each with a probe in `NOT_SEEN` that passes unseen (the last has its own test, `test_an_allowed_match_used_as_sql_adds_no_match`). This list holds every gap found so far; it is not a proof that nothing else gets past the scan. The test role (`tests/test_db_role.py`) is the guard.
    - a name built from pieces at run time (`"r" + "aw"`, `"".join(["r", "aw"])`);
    - a name read from the environment, settings or a file;
    - `getattr` with an attribute name built at run time;
    - a loader or register call without `schema=`, which falls back to `raw` (the throwaway fixture's lock check catches this on its own connection only);
    - SQL read from a file that is not Python;
    - `set schema 'raw'`;
    - a multi-line string with `search_path` and the name on different lines and SQL after;
    - a database-qualified name at the end of a string (`"delete from mesh.raw" + ".snapshot"`);
    - an f-string with a replacement field directly before the name (`f"delete from {p}raw.snapshot"`);
    - a printf-style placeholder directly before the name (`"delete from %sraw.snapshot" % p`);
    - a SQL comment between the name and the dot (`raw/**/.snapshot`);
    - a Unicode-escaped identifier (`U&"\0072aw"`);
    - the `schema` default read at run time (`inspect.signature`, `__kwdefaults__`);
    - an alias or variable holding an ALLOWED match later used as SQL: ALLOWED counts matches, not uses.
  - The scan is capped (Casey, issue #55, 2026-11-17, item 4): a gap found later goes into this list, not into new code. The test role every test connects as, with no privilege on `raw`, `raw_dev_wh` or `raw_dev_ta` (Casey, issue #55 comment 6961809084, item 10, and PR #64 comment 6968763718, item 5), is the guard for everything the scan cannot see. The watched names are `tests/raw_schema.py` `REAL_SCHEMAS`: `raw`, `raw_dev_wh` and `raw_dev_ta`.
- Reduction: `uv run --frozen python -I -m ingester.reduce`. It ran once, on 2026-11-14, and cannot run again: its input archive was deleted that day.
- Load: `uv run --frozen python -m ingester.load <snapshot id>`.
- Capture and gate: `docs/adr/0003-spike/README.md`.
- Engine inputs for a tile, from a checkout (it runs the spike scripts under `docs/adr/0003-spike/`), in Git Bash:

  ```
  unset VIRTUAL_ENV
  UV_SYSTEM_CERTS=true uv run --frozen python -I -m ingester.engine_inputs \
    --snapshot meshtastic-capture-2026-10-22 --tile x72y429 \
    --dem-snapshot 3dep-1m-mo-saintlouis-2017-x72y429 --expect-pairs <n> \
    --out <data folder>/configs/x72y429
  ```

  `<data folder>` is the host folder outside the repository that `SNAPSHOTS_HOST_DIR`, `SNAPSHOTS_DIR` and `RUNS_HOST_DIR` in `.env` point into; the output folder must be outside every git checkout.

  `<n>` is the pair count the contract's rules give on the snapshot (Casey: `--expect-pairs` is set to the count the contract gives). It was 8 under the spike's rules; the lead's real run sets it, and no figure from real data is in this repository.

  It writes `tx_sites_real.parquet` (`site_id`, `geometry`, `box_south_i`, `box_north_i`, `box_west_i`, `box_east_i`, `role`: `both_ends_gateway` or `gateway_only_gateway`) and `rx_real.parquet` (`rx_id`, `geometry` and the same four edges) in EPSG:26915 (ADR 0008). The four edges are the `lnk_02` box each node's pairs used, `LinkBox`'s half-open edges in 1e-7 degrees, int64, unchanged; there is no `box_half_width_m` column. The point is the box centre as `terrain.boxes.EdgeBox.centre_xy_m` gives it, which the engine checks to 1 mm, and the DEM edge check runs the engine's grid on the whole box (`EdgeBox`), so a box whose inscribed square would fit can fail on its long side (the stricter check Casey accepted on PR #73). The grid is widened to the GPS error floor a prepared run writes, `engine.prepare.run_config.POSITION_FLOOR_M` (5 m, ADR 0009), as `engine.prepare`'s own check widens it, so a box under 10 m across near the DEM edge fails here exactly when prepare would leave that site out of the run, or refuse the run for that receiver. The tile test (`row_state`) passes a floor of 0: it asks whether the `lnk_02` box as the firmware sent it lies in the tile. `engine.prepare` accepts the folder and the engine draws each endpoint inside its edges. Both files carry `mesh_terrain:positions` = `real` in their Parquet metadata. Casey, issue #44, 4 (a): ingest-eng's layers "real", the grid and fixtures "synthetic". The lead's interface note on issue #44 (2026-11-16) adds that a layer is `synthetic` only when every row is made up, and any real row makes it `real`. The engine does not read the key yet.
  - Both layers (with `--sites-only`, the site layer and the local run report) are written into `engine-inputs.partial/` inside the output folder and moved to their names only when all are complete. A refusal (exit 2) writes nothing. Any other failure raises after removing what the run wrote: the layers, the staging folder, and the output folder and parents it created. An existing layer or staging folder is refused and left as it is.
  - One merged snapshot only (Casey, issue #55 comment 7016583529, item 4). With or without `--sites-only`, the command refuses (exit 2, nothing written) a capture snapshot whose manifest `brokers` does not list both `mqtt.meshtastic.org` and `mqtt.meshstl.org`, such as one written by the capture command from a single broker. It reads one snapshot and groups a broadcast's copies within it, while `pos_04`'s MeshSTL flag reads every copy of a delivery in any snapshot (Casey, issue #55 comment 6985802330, item 7), so every copy must be in that one snapshot. The reduction lists a broker in the manifest only when it read at least one of that broker's capture files, so a missing or empty folder leaves it out (`ingester.reduce.brokers_read`; Casey, issue #55 comment 7017280290, item 1). `meshtastic-capture-2026-10-22`'s manifest, written before that change, lists both brokers.
  - Positions by the contract's link-hour rules (`link_rules`, item 4 unit). The pairs are the (relayer, gateway) with at least one kept link-hour on the merged snapshot, both brokers together (Casey, issue #55, Q1). Each pair carries the box its counted receipts used at each end, over its kept hours: under `lnk_02` with the floor, the box around merged fixes, one box per end for the hour and the half-open 32-bit cell. Only receipts in kept link-hours set a pair's box (ADR 0003, Link-rule amendment, "Pair boxes, per-pair rows and the MeshSTL flag"; Casey, issue #55 comment 6985802330, item 2, (b): "only the receipts the validation uses must agree on position"). A pair whose end used more than one box over its kept hours counts in the 2026-11-08 counts check and is then dropped, as a straddling pair is (item 3), with a line `dropped <kind> <relayer> to <gateway>: <end> used more than one box in its kept hours` (Casey, issue #44, 2026-11-17: "a pair whose receipts used more than one box is dropped and reported to me"). A kept pair whose hours not kept show another box on their counted receipts is kept, and listed locally: `pairs kept with another box in hours not kept: <n> (...)`, then `kept pair <relayer> to <gateway>: <end> used another box in hours not kept` (item 2: "kept but reported to me in the session, never on issue #44"). `--expect-pairs` compares the contract's count, the two-box pairs included. A node is placed once per pair, at the box that pair used (Casey, issue #44, 2026-11-17: "a moving node is placed per pair"), one layer row per distinct box. A node whose pairs all used one box (all four edges equal) is one row with its pseudonym as `site_id` or `rx_id`; a node at two or more places gets a row per box with `<pseudonym>.<n>`, n counting its boxes from 1 in the order the capture's pairs (sorted by relayer, then gateway, relayer end first) first use them, so the id says nothing of where a box lies (`tile_selection.site_row_ids`). `engine.prepare` takes these ids: `site_id` matches `engine.run.SITE_ID` and every id in a layer is distinct. Example: G3 heard with C at its own box and with another relayer at a box 2 km west gives the rows `<G3>.1` and `<G3>.2`.
  - In or out of the tile, row by row (Casey, issue #55 comment 6985802330, item 6): a row is `in` when its box, taken as its four corners in EPSG:26915, lies inside the tile, `out` when it lies outside and `split` when it crosses the tile edge; box and tile are both half-open, so a box that only touches the tile edge does not straddle it. Each pair is judged by its own rows. For the 2026-11-08 counts check only, a node counts as touching the tile in every pair it is in when any of its boxes is in or across the tile.
  - Sites by tile membership (Casey, issue #44, busiest pair, 2026-11-17). The sites are the in-tile gateway of every pair that touches the tile, as the 2026-11-08 counts define touching: the both-ends pair's gateway, then each gateway-only pair's gateway in the capture's pair order (sorted by relayer pseudonym, then gateway pseudonym), each gateway once, `both_ends_gateway` first. The receiver is the both-ends pair's relayer. The 2026-11-08 note (`docs/measurements-2026-11-08.md`) named its sites as the gateway ends of the two busiest pairs without recording how it ranked them; that ranking rule is lost, and the x72y429 run is chosen by tile membership. The ranking stays in `busiest_two`, by link-hours over both runs, ties broken by receipts in those link-hours (Casey, issue #44, engine_inputs Q2 (a), 2026-11-16), for wherever a ranking is needed later (Casey, issue #44 comment 6956865492, 2026-11-17: "'Busiest' keeps (a), link-hours with ties broken by receipts, wherever a ranking is needed later; (c) is not adopted because it counts an hour twice when both brokers heard it"). Nothing selected depends on it. The stdout still shows each pair's link-hours over both runs, public and MeshSTL, and its receipts, for the local record, and a `sites by tile membership:` line stating the rule.
  - Without `--sites-only` (below), it refuses when the pair count differs from `--expect-pairs`, the tile does not hold exactly one pair with both ends, two pairs with only the gateway end and three pairs touching it (so none with only the relayer end), the both-ends pair or a gateway-only pair is dropped (next item), the DEM snapshot is refused by the engine's reader, the output folder is inside a git checkout, or a layer exists.
  - Straddling rows and dropped pairs (Casey, issue #44, engine_inputs Q1 (a), 2026-11-17, read for rows in issue #55 comment 6985802330, item 6: "only the pair whose row straddles the tile edge or fails the edge check. That node's other pairs, whose rows lie inside, stay"). The counts run first over every pair, two-box pairs included, with the touching rule above. Then a pair is dropped when its relayer's or gateway's row straddles the tile edge, when the row the run places for an end fails the DEM edge check, or when it used more than one box at an end; the node's other pairs stay unless they fail too. The kinds of the pairs follow their own rows (a straddling row counted as in), a two-box pair's the counted states. Each pair's own row decides its kind and its gateway's role (Casey, issue #55 comment 6990646633, item 3: "(b), each pair's own row decides its kind and its gateway's role"). A moving node near the tile edge can make that differ from the counts check, one of its pairs' rows inside the tile and another outside, so every such pair gets a local line `kind differs, pair <relayer> to <gateway>: <kind> by its own rows, <kind> by the counts check; for Casey in the session (issue #55 comment 6990646633, item 3)`, kept in the local run report, and no run stops for it. When the counts pass but no pair has both ends in the tile by its own rows, there is no receiver row, and a strict run does not stop (Casey, PR #70 comment 6992903491, (b)): it writes the sites and the local report and no `rx_real.parquet` at all, so `engine.prepare` refuses the folder unless `--no-real-receivers` is passed, and a line of its own on the terminal and in the report reads `no real receiver: this strict run produced no real receiver and wrote no rx_real.parquet, because no pair has both ends in the tile by its own rows; engine.prepare refuses this folder unless --no-real-receivers is passed (Casey, PR #70 comment 6992903491)`. Dropping the both-ends pair or a gateway-only pair refuses (exit 2) after the drop lines are printed and before anything is written, so the lead can bring it to Casey before `engine.prepare`. With the count check as it is (three pairs touching, all three selected), an unselected pair that touches is a fourth touching pair and fails the count check before any drop, so a drop that reaches the drop step is always of a selected pair. The straddle and two-box drop lines print before the count checks run (Casey, PR #51, (a): "The drop lines print before the count checks, locally only."), so every refusal shows which pair and which end caused it. Each names the pair's kind (`both-ends pair`, `gateway-only pair`, `other pair`) when those checks would pass, and `pair (kind not determined)` when one of them would refuse. A DEM edge check line needs the placed row, so it prints after placement; no drop line prints twice.
  - Worked example on the synthetic fixture (`tests/engine_inputs_fixture.py`): A to G1 has both ends in the tile, and B to G2 and C to G3 only their gateway. The sites are G1 (`both_ends_gateway`), then G3 and G2 (`gateway_only_gateway`, C to G3 first because C's pseudonym sorts before B's), and the receiver is A. With `busy_outside_pair=True`, D to E, east of the tile, has 6 link-hours, more than any other pair; it touches nothing, so the sites are the same. M sends two boxes 1.7 km apart and is placed at the one its hour's counted receipts used. With `moved_in_pair=True`, C to G3 has a fourth kept hour where G3 reads a box 2 km west by the 30-minute fallback: the counts check counts the pair and passes, then the run prints `dropped gateway-only pair <C> to <G3>: gateway used more than one box in its kept hours` and the strict run refuses on the dropped selected pair. With `moved_short_hour=True` that hour has two receipts and is not kept, so C to G3 is kept at G3's own box and listed as `kept pair <C> to <G3>: gateway used another box in hours not kept`; under the other reading, every counted receipt, the pair would be dropped. `straddler`, `moved_a` and `moved_g3` give a node a second place in a second pair with an invented partner: with `straddler="G2"`, G2 used its own box with B, inside the tile, and a box across the west edge with its partner, so only the partner's pair is dropped, and the strict run refuses on `3 pairs have only the gateway end in x72y429, not two` after that drop line. With `g3_at_edge=True`, G3's box crosses the east edge and C to G3 is dropped as straddling; with the DEM `NARROW_DEM_BOUNDS_M`, G3's own box lies inside the tile but fails the DEM edge check. With `contradicted_d=True`, E's NeighborInfo names another node with D's byte, so D's three direct hops are dropped and counted (`lnk_01_direct_hop_contradicted 3`) and D to E is no pair. Three options add boxes the rules read as one place or do not read, so the layers stay as they are: `nested_g1=True`, `nested_g3=True` and `ignored_a=True`.
  - Its stdout gives the pair count under the contract, each pair's link-hours (with a public and with a MeshSTL receipt) and receipts, the data-quality line `data-quality counts: lnk_01_direct_hop_contradicted <n> (...); one_box_dropped_hours <m> (lnk_02)`, a line per pair dropped for its boxes, and then pseudonyms, roles, link-hours, box half-widths, the precise flag and the DEM check per node (the engine's rule on the DEM snapshot's bounds), and one line per end that drops a pair (both pseudonyms, `relayer` or `gateway`, and `straddles the tile edge` or `fails the DEM edge check`), never a coordinate. Those lines narrow where a node is, so they are read locally. Only the last `counts for issue #44` line is posted (Casey: counts only on issue #44); it gives the pair counts, the pairs touching the tile, the nodes selected, the DEM check passes and fails, and the pairs dropped in all and for each reason (a pair dropped for both reasons counts under each), with no pseudonym.   - Sites only, the x72y429 run with no real receiver (Casey, 2026-11-17, engine_inputs (c)): add `--sites-only` to the command above. It is accepted only with `--tile x72y429`, since corridor runs keep the strict checks; any other tile refuses (exit 2) before anything is read. It writes `tx_sites_real.parquet` alone, with the same columns, roles and `real` marker, through the same staging folder, and never `rx_real.parquet`; terrain-rf-eng's `python -m engine.prepare x72y429 --folder <folder> --no-real-receivers` then takes the 400-point synthetic grid as the only receivers. The 2026-11-08 counts check still runs and prints one line, `counts check against 2026-11-08: pass` or `differs (...)` naming every count that differs, and does not refuse. The drop lines print at the same points as without the flag, and no dropped pair stops the run; since the counts check cannot refuse first, every straddle drop line names its pair's kind (`both-ends pair`, `gateway-only pair` or `other pair`), never `pair (kind not determined)`. The candidates are the in-tile gateways of the site rule above, but their roles follow each pair's own rows (Casey, issue #55 comment 6985802330, item 6): a relayer that touches the tile only through another pair's row leaves this pair gateway-only, so its gateway is written as `gateway_only_gateway`. A gateway is written once per box its pairs used under `lnk_02`, unless it straddles the tile edge or the row fails the DEM edge check. Each one left out gets a local line `left out <pseudonym> <role>: <reason>`, with the row id, the reason being `straddles the tile edge` or `fails the DEM edge check`. A run with no site left refuses (exit 2) and writes nothing: `no site left; all <n> in-tile gateways were left out`, or `no site: no pair touching the tile has its gateway in it` when there was no candidate. No relayer is placed, so no receiver is chosen, a relayer with more than one box does not refuse the run, and no relayer is DEM-checked. The `counts for issue #44` line ends with `sites written <n>, left out <m>; no real receiver written; relayers not DEM-checked`, with no pseudonym. An existing `rx_real.parquet`, site layer or staging folder in the output folder is refused, so the sites never sit beside an earlier receiver layer. Local run report (Casey, issue #55, 7: "Also write the counts line and every left-out gateway line into the local run report, not only the terminal. Nothing public."): beside the layer, through the same staging folder and only when the layer is written, the run writes `engine_inputs_report.md`, a heading, a local-only note, the two snapshot ids, and in a text block the data-quality line (Casey, PR #66, Q4 (a): "count these drops as a data-quality count in the run report"), the other-box lines (Casey, issue #55 comment 6985802330, item 2), the drop lines, the `kind differs` lines, the counts check line, the site rule, each per-gateway line, the sites-only rule, each `left out` line and the counts line, in the order they printed. It names pseudonyms and ties them to roles and the tile edge, so it is local only, like the layer: the output folder is refused inside any git checkout, the report is never committed, posted or published, and only its last line, the counts line, goes on issue #44.
