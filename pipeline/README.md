# pipeline

The Dagster code location for the batch lane: raw loaders, dbt assets, terrain features and marts. Today `pipeline/definitions.py` registers two things: the `raw/mqtt_snapshot` asset, which `ingester/` defines and which loads one registered snapshot into the `raw` schema, and the dbt assets with their CLI resource. `pipeline/common/` holds the typed settings and the structlog setup every asset shares, and the snapshot lifecycle every input shares.

`pipeline/common/snapshot.py` is that lifecycle (contract rule `snp_01`). A snapshot is a dated folder of input files that never changes once finished. A command that writes one calls `start_snapshot(root, id)`, which creates `<root>/<id>.partial/`, writes its files there, calls `write_manifest(partial, metadata)`, which lists every file with its sha256 and size beside `snapshot_id`, `capture_date`, `source_url`, `licence` and `seeds`, then `finish_snapshot(partial)`, which renames the folder to `<root>/<id>/`. A loader finds it with `snapshot_folder(root, id)` and records it in `raw.snapshot` with `register_verified(conn, folder)`, which checks every file against the manifest first and inserts nothing for a `.partial` folder or a mismatch. Worked example: a 1 m elevation tile written as `<root>/3dep-1m-mo-saintlouis-2017-x72y429.partial/tile.tif` gets a manifest with that file's sha256, becomes `<root>/3dep-1m-mo-saintlouis-2017-x72y429/`, and registers as one `raw.snapshot` row; registering it again adds nothing. A writer that needs more fields or checks passes `required` and `check` to `write_manifest`, as `ingester/snapshot.py` does for a capture. The module does not download or read file contents, does not create the `raw` schema (`ingester/sql/raw_tables.sql` does, through the loader), and never removes a file or a `.partial` folder.

Run it locally with `make up` and open http://localhost:3000. On the host, `uv run dagster dev -m pipeline.definitions` works too once `.env` exists. Nothing here is scheduled: there are no schedules or sensors, and an asset runs only when someone materialises it.

Deliberately not here: the capture command and the reduction (`ingester/`, run by hand on the host, never from Dagster; ADR 0005), terrain mathematics (`terrain/`), and SQL transforms (`dbt/`). Assets in this package orchestrate those; they do not reimplement them.
