# ADR 0006: Add ITU-R P.1812 through Py1812 beside ITM, behind one path-loss function

Date: 2026-11-14
Status: proposed
Proposed by: terrain-rf-eng
Decided by: Casey

## Context

Phase 3 of `docs/PLAN.md` (the Stack table and the Tasks line) adds a fifth model beside free space, knife edge, Okumura-Hata and ITM (ADR 0002): ITU-R P.1812, run through the Python package Py1812 pinned to a git commit. The Tasks line leaves six questions to this ADR, and contract row `ter_06` adds a seventh, the Okumura-Hata threshold. Terms, defined once:

- ITU-R P.1812 is the International Telecommunication Union's method for predicting loss over terrain from 30 MHz to 6 GHz. Like ITM it reads the ground profile between the antennas; unlike ITM it also reads a clutter height at every profile point. Version 8 (September 2025) is current.
- Clutter is what stands on the ground between the antennas: buildings and trees. Its height is the surface height minus the bare-earth height. P.1812 calls it R, the representative clutter height, in metres at each profile point.
- Leaf-off and leaf-on: deciduous trees are bare (leaf-off) from about November to April and in leaf (leaf-on) from about May to October. Leaves hold water, which absorbs and scatters a 915 MHz signal, so a tree in leaf costs more signal than the same tree bare.
- The ITU digital maps are two world grids at 1.5 degree spacing that ship as text files with the Recommendation. DN50.TXT gives DN, how fast the air's refractive index falls over the lowest kilometre, which sets how much the atmosphere bends a signal back toward the ground. N050.TXT gives N0, the refractivity at sea level, used only on paths long enough for tropospheric scatter. P.1812 reads both at the path's midpoint. At St. Louis DN is 39.1, an effective earth radius factor of 1.33, the same 4/3 our own line of sight code uses. They are "an integral part of the recommendation and may not be reproduced, by any means whatsoever, without written permission of ITU" (the wording Py1812 repeats in its build script), so they are never committed, baked into an image or published.
- Basic transmission loss is the loss between two ideal antennas with no gain; transmit power and antenna gains are not in it. Every model below returns this quantity.

The spike (`docs/adr/0006-spike/`) installed Py1812 at the recommended commit in a scratch environment, built the map file outside the installed package and repeated the 2026-11-08 test call. On a flat inland 10 km path at 915 MHz with 2 m antennas P.1812 gives 149.48 dB, ITM 151.76 dB (ADR 0002) and free space 111.68 dB. A call takes 2.1 ms on a 1 001-point profile and 15.7 ms on a 10 001-point one.

## Options

### 1. How Py1812 is installed and pinned

Py1812 (github.com/eeveetza/Py1812, Ivica Stevanovic, Swiss Federal Office of Communications) has no PyPI release and no tags. On 2026-11-14 the head of `main` is still 6c9061dd (2026-08-28, "Fix for Issue #11"); the repository is active and has no open issue. The licence lets anyone use, modify and redistribute the code, asks for a dated notice on changes and an acknowledgement, and the author confirmed it as MIT or BSD style in issue #13.

1. A uv git dependency, `py1812 @ git+https://github.com/eeveetza/Py1812@6c9061dd`. Advantage: the plan's wording; `uv.lock` records the commit. Cost: uv runs the `git` program for a git source (tested: "Git executable not found"), and the Dagster image has none, so the image gains git plus a certificate line for the Norton secret.
2. A uv archive dependency at the same commit, `py1812 @ https://github.com/eeveetza/Py1812/archive/6c9061dd022e93c84169059a016643926ce89964.tar.gz`. Advantage: no git anywhere; `uv lock` records the archive's sha256 (`03d7c5bd...`, tested in a scratch project) and `uv sync --frozen` checks it, the pattern the Dockerfile already uses for ITM. Cost: GitHub builds archives on request, so a change on GitHub's side fails the install on the hash until someone updates the lock, the same risk STATUS records for ITM and H3 core.
3. A vendored copy of `P1812.py` (3 170 lines) under `terrain/`. Advantage: no download at install, and the map loading can be rewritten. Cost: third-party code in the repo outside ruff and mypy, a dated notice per edit, and each upstream fix merged by hand; upstream shipped four fixes in 2026.

### 2. Where the maps and P1812.npz live, and how the image and CI get them

Py1812 loads `P1812.npz` when it is imported, from its own installed folder (`P1812.py` line 19), and the upstream build script writes that file into whatever folder it runs in. Importing without the file raises `FileNotFoundError` naming the site-packages path.

1. Upstream in place: copy the two text files into the installed package's `maps/` folder and run the build there. Advantage: no code of ours. Cost: every environment, worktree and image needs the step again, and an image built this way carries ITU data, which becomes redistribution the day an image is pushed (Phase 6).
2. A map snapshot plus an import redirect. `make p1812-maps` downloads the public zip (636 KB, sha256 `d3a51f29...`), extracts the two files and builds `P1812.npz` into the snapshot `itu-r-p1812-8-202509` under `SNAPSHOTS_DIR`, with a `snp_01` manifest (source URL, ITU's licence sentence, sha256 of the zip, both files and the npz). A setting `p1812_maps_dir` names the folder. `terrain/p1812.py` raises `RuntimeError` naming `make p1812-maps` when the npz is missing, checks the npz against the manifest's sha256 as `snp_01` requires of every snapshot file, and then imports Py1812 with `importlib.resources.files` patched for the length of the import, so the one map lookup reads the snapshot. Advantage: upstream code untouched, nothing written into site-packages, and the read-only `/snapshots` mount the Dagster containers already have brings the maps in, so no image holds them. Cost: the redirect depends on how line 19 loads the maps; an upstream change there fails the import loudly, and only when we move the pin.
3. A vendored fork (option 1.3) whose loader takes a path. Advantage: no redirect. Cost: those of option 1.3.

CI has no maps and no network for the engine fixture run. Under option 2.2 the tests and the CI fixture run point `p1812_maps_dir` at a synthetic npz that a pytest fixture writes into a temporary folder: constant grids of DN 40 and N0 325 in the real shape, made-up values that are not ITU data. The text of the manifest's existing `models` entry names the map source (`Py1812 6c9061dd, P.1812-8, maps itu-r-p1812-8-202509`, or `maps synthetic`), so nobody mistakes a CI number for a real one. A host target `make check-p1812` repeats the 149.48 dB call against the real maps, as `make check-itm` does for ITM. Fetching the zip in a CI step was considered and rejected: it puts itu.int's availability into every CI run and tests nothing the synthetic maps do not.

### 3. One function for every model (sketch)

```python
Model = Literal["fspl", "knife_edge", "hata", "itm", "p1812"]

@dataclass(frozen=True)
class PathProfile:
    """Ground and clutter along one straight path, EPSG:26915."""
    distance_m: FloatArray          # from tx, ascending, starts at 0, uniform step
    ground_m: FloatArray            # metres above NAVD88, no earth curvature applied
    clutter_m: FloatArray | None    # metres above ground; None where only the metro DEM exists
    tx_xy_m: tuple[float, float]    # easting, northing
    rx_xy_m: tuple[float, float]

def path_loss_db(
    model: Model,
    profile: PathProfile,
    frequency_mhz: float,
    tx: AntennaProfile,             # engine/profiles/<name>.yaml: height_m, gain_dbi, polarisation
    rx: AntennaProfile,
    *,
    hata_variant: Literal["urban", "suburban"] | None = None,
) -> float | None:
    """Median basic transmission loss in dB, antenna gains excluded."""
```

- It returns None only for `p1812` without clutter (question 4). It raises `ValueError` for a zero-length path, fewer than five samples, or `hata` without a variant, and `RuntimeError` naming the install step when the ITM library or the P.1812 maps are missing.
- The profile carries ground heights without curvature. ITM and P.1812 apply their own effective earth radius; knife edge, line of sight and Fresnel apply k = 4/3 inside `terrain/`. A curved profile fed to ITM or P.1812 would count the bulge twice, which is the kind of bug the 10 dB cross-check exists to catch.
- Units change at the model edge only: MHz to GHz and metres to km for P.1812, metres to km for Hata, and the endpoints from EPSG:26915 to EPSG:4326 through one pyproj transformer for P.1812's map lookup. No arithmetic on degrees.
- Endpoint sampling sits outside: the sampler calls the function once per draw and model and keeps the median and interquartile range.

### 4. Clutter as P.1812's R

Clutter height at each profile point is max(DSM minus DEM, canopy height where the canopy is nonzero), from the 1 m layers. The DSM (digital surface model) is the first-return lidar surface, the tops of roofs and trees. Every 3DEP lidar collection over the MSA is recorded as leaf-off in the USGS lidar index; the St. Louis 2017 collection, which covers the city and county, was flown in February 2017. The capture ran on 22 to 25 October 2026, with the trees mostly still in leaf. A leaf-off lidar pass sees a deciduous tree as bare branches: some pulses return from the branches, many reach the ground, so DSM minus DEM understates the tree. The Meta and WRI canopy height map comes from satellite imagery that is 40 to 68 percent leaf-on (`docs/measurements-2026-11-08.md`). Taking the larger value keeps buildings from the lidar and each tree at the taller of its two estimates. Three limits remain and go in the write-up: the lidar is from 2017 and the canopy imagery from 2018 to 2020, years before the capture; a height says nothing about how dense a crown is, which is what leaves change; and P.1812 treats clutter as an obstacle to bend over, not foliage to pass through.

Py1812 adds R to every profile point except the two terminals (`g = h + R`, then `g[0] = h[0]` and `g[-1] = h[-1]`), so a 2 m antenna beside a 15 m tree sees the tree one sample away.

1. Where only the metro DEM exists, `p1812` is null. Advantage: matches "clutter null, never zero"; P.1812 with R = 0 is a second bare-earth model, which ITM already provides. Cost: if the corridors are cut (plan cut order item 2), P.1812 covers only the test tile's links.
2. Where only the metro DEM exists, run P.1812 with R = 0 and label it. Advantage: a P.1812 number on every link. Cost: one column holding two models, or a new column, which changes `docs/INTERFACE.md`.

Under option 4.1 the engine refuses a config that lists `p1812` and names neither a DSM nor a canopy snapshot, so a run cannot produce an all-null column by accident.

### 5. Antenna profiles for validation

1. `mesh_node` (2 m, 0 dBi, 22 dBm) at both ends, as the plan says. Advantage: nothing in the capture says which gateways stand on masts, and the Phase 4 mixed model's random intercept per relayer and per gateway absorbs a constant offset per node (power, gain, cable). Cost: a tall gateway's height gain changes with distance, so part of it stays in the residual; the Phase 4 rows at 1 m and 5 m show how much.
2. `mesh_node` at the relayer and `site_gateway` (10 m, 3 dBi) at the gateway. Advantage: right for the gateways that are on masts. Cost: a guess applied to every gateway, most of which are home nodes like any other.
3. A height per node from its reported altitude minus the DEM. Advantage: a measured height for each node. Cost: GPS altitude errors of tens of metres and hand-entered altitudes make it worse than a fixed guess.

### 6. P.1812 settings

Fixed by the plan: p = 50, the time percentage (the median; Py1812 accepts 1 to 50), and zone 4, inland, at every point; the MSA's rivers and lakes are far smaller than the water bodies P.1812 treats as sea. Fixed here as Py1812 defaults the plan does not name: location percentage pL = 50 with sigmaL = 0, so the result is also the median over locations; distance to the coast dct = dcr = 500 km, since the nearest sea coast is about 1 000 km away; DN and N0 from the maps at the path centre; flag4 = 0, so the terrain profile is used; debug = 0, because debug mode writes a CSV into the working directory. Polarisation comes from the profile (vertical). Transmit power and gains stay at their defaults because they enter only the field strength output, and we read the loss. ITM keeps the settings of ADR 0002.

Choices the plan leaves open:

- R per profile point as measured, or a representative value per land class (Py1812 ships class tables, one for NLCD, which the plan dropped). Recommend per point: it is what the plan's clutter rule describes.
- A negative DSM minus DEM (lidar noise, water) floored at 0 before the maximum. `ter_05` already requires non-negative clutter, so this reads the rule rather than changing it, but the clutter rule is Casey's.
- The profile step: P.1812 gets the profile every model gets, 10 m on the metro DEM and 1 m on the 1 m layers. At 15.7 ms a call, 150 link-hours times 16 draws at 1 m take about 40 s.

### 7. The Okumura-Hata variant threshold (`ter_06`)

Okumura-Hata is Hata's empirical formula fitted to Okumura's measurements around Tokyo, valid for 150 to 1 500 MHz, 1 to 20 km, base antennas 30 to 200 m and mobile antennas 1 to 10 m. The suburban variant is the urban one minus 2(log10(f/28))^2 + 5.4 dB, 9.96 dB at 906.875 MHz. With 2 m at both ends every link is below the base antenna range, so Hata is extrapolated everywhere; it stays as a baseline with the antennas as given, not clamped to 30 m, and the results say it is out of range.

1. Urban when the mean of the two endpoints' building footprint shares within 100 m is at least 0.20, suburban otherwise. Each endpoint's share is the median over the draws, so a link-hour has one variant. Advantage: both ends count equally, as the loss does. Cost: a link from a dense block to a sparse suburb falls on whichever side of 0.20 the mean lands.
2. Urban when either endpoint reaches the threshold. Advantage: one end in a dense block, such as a downtown gateway, makes the link urban. Cost: that one end outweighs a suburban other end.
3. Urban when both do. Advantage: urban only when the whole link is built up at both ends. Cost: few links outside downtown qualify, so the variant would hardly vary.

The 0.20 is reasoned, not measured: as a rough figure, blocks of detached houses cover 10 to 20 percent of their ground with buildings, row houses and commercial streets 30 percent or more. The engine brief measures the shares at the link endpoints from the OSM snapshot and reports how many link-hours change variant between 0.15 and 0.25 before the value is used.

Proposed, waiting on Casey.
