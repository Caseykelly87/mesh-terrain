## Deviations from the plan still in effect

- The object store is `bitnamilegacy/minio` pinned by digest, not `minio/minio`. Upstream MinIO archived the community server and client in 2026 and withdrew the images and binaries from Docker Hub, quay.io and dl.min.io; the Bitnami legacy build of the last community release is the only pullable image. It is frozen and may be removed; kept by decision in ADR 0004. The plan's stack table still says MinIO; nothing else in the design depends on the vendor, since the raw zone is S3-shaped.
- The warehouse image installs `postgis_raster` as an extension because `h3_postgis` declares it as a required dependency. No table stores rasters; the plan's rule against PostGIS raster is about storage and still holds.
- h3-pg is built from `github.com/postgis/h3-pg` (the `zachasme/h3-pg` repository named in the plan was archived and moved there) at tag v4.2.3, commit a26630b8.
- ADR 0001 said PostgreSQL 16; the warehouse is PostgreSQL 17 with PostGIS 3.5 per ADR 0004, and the plan's stack table already says so.
- `staging.stg_msa_boundary` rejoins two WKT chunks with `string_agg(geometry_wkt, '' order by part)`, beyond the staging rule of casting and renaming only, because dbt cannot load a seed field over 131,072 characters and the boundary WKT is 179,994. The lead decided to keep the two exact chunks rather than simplify the polygon to one row. No ADR: the grain is unchanged and it is not a stop item. PR #7.
- Note for every agent: the plan was revised on 2026-10-21 after verifying two public-broker behaviours (hop_limit rewritten to 0; positions limited to 10 to 16 bits). The link is relayer to gateway, the 1 m DEM is out of scope, and ADR 0003 (accepted 2026-10-31) sets the link source, position source, position rule and area. Read the section "Two constraints of the public broker" in docs/PLAN.md before any Phase 1 or Phase 2 work.

## Interfaces agreed between agents, not yet in code

- platform-eng to ingest-eng: the Phase 1 ingester service uses `restart: on-failure`, the one exception to `restart: "no"`. The ingester is specified to exit 0 on its halt condition (ADR 0005, being drafted), so `on-failure` would not restart it then; it restarts only after a non-zero exit. Docker's restart-policy documentation states that `on-failure` does not restart a container when the daemon restarts. Confirm that on this host when the service is added, because a container that is running when Docker Desktop quits records a non-zero exit (255 for the warehouse and object store on 2026-10-28). The compose-smoke guard that requires `no` on every service must exclude the ingester at the same time. ingest-eng owns the service and its exit codes; platform-eng owns its entry in `docker-compose.yml`. Removed from this list when the service is in Compose.
- platform-eng to terrain-rf-eng: `terrain/itm.py` (Phase 3) loads the library from `settings.itm_library_path`, not a hard-coded path, so a host-side build can point elsewhere. The ctypes signature for `ITM_P2P_CR_Ex` stays in `terrain/itm.py`; the image only guarantees the file exists and exports the four `ITM_P2P*` symbols (the build fails otherwise).
- warehouse-eng to ingest-eng: the Phase 1 spike clips positions with `select st_contains(geom, st_setsrid(st_point(lon, lat), 4326)) from staging.stg_msa_boundary` (columns `geoid`, `name`, `geom`; one row). The seed CSV differs from the brief in one way: the WKT is in two chunks with a `part` column, so a direct read of the CSV must concatenate `geometry_wkt` in `part` order. Removed from this list when the spike's query is in code.
